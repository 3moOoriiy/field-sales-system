# Deployment guide — GitHub + Render

## 1. Push to GitHub

```bash
cd D:/3mr/field-sales-system

# Initialise the repo
git init -b main
git add .
git commit -m "Initial commit"

# Create a GitHub repo at https://github.com/new (e.g. "field-sales-system"),
# then connect and push:
git remote add origin https://github.com/<YOUR_USERNAME>/field-sales-system.git
git push -u origin main
```

## 2. Deploy on Render

### One-click via Blueprint

1. Sign in to https://render.com (free)
2. Click **New +** → **Blueprint**
3. Connect your GitHub account, select this repo
4. Render reads `render.yaml` and creates **3 services automatically**:
   - `field-sales-api` (Web Service, Docker) — the backend
   - `field-sales-admin` (Static Site) — admin dashboard
   - `field-sales-pwa` (Static Site) — agent PWA

### Set secrets

Go to the **field-sales-api** service → **Environment**, set:

- `DATABASE_URL` → paste your Neon connection string

`JWT_ACCESS_SECRET` and `JWT_REFRESH_SECRET` are auto-generated by Render.
The other vars are pre-configured in the blueprint.

### Update CORS

After Render deploys, you'll get the actual URLs (Render appends a random
suffix on free plans, e.g. `field-sales-admin-abc1.onrender.com`).

Go to **field-sales-api** → **Environment** → edit `CORS_ORIGINS`:

```
https://field-sales-admin-XXXX.onrender.com,https://field-sales-pwa-XXXX.onrender.com
```

Click **Save**, the backend redeploys.

### Run migrations + seed (one-time)

In the **field-sales-api** service → **Shell** tab:

```bash
npx prisma migrate deploy
npm run seed
```

(For free tier: open the shell and the service wakes up.)

## 3. Open the apps

- **Admin**: `https://field-sales-admin-XXXX.onrender.com`
- **Agent PWA**: `https://field-sales-pwa-XXXX.onrender.com`
- **Backend API docs**: `https://field-sales-api-XXXX.onrender.com/api/docs`

Login: `superadmin / Admin@123` (admin), `agent01 / Agent@123` (PWA).

## 4. Custom domain (optional)

For each Render service: **Settings** → **Custom Domain** → add your domain
(e.g. `app.yourcompany.com`). Render gives you DNS records to set at your
registrar. SSL is automatic.

Don't forget to update `CORS_ORIGINS` and `VITE_API_URL` / `VITE_AGENT_API_URL`
to match your custom domain after.

## Free tier limits to be aware of

| Service | Limit |
|---------|-------|
| Backend (Web Service) | Sleeps after 15 min of no traffic. First request wakes it (~30s cold start) |
| Static Sites | No sleep, free CDN, always fast |
| Bandwidth | 100 GB/month free |
| Build time | 500 build-min/month free |

To prevent the backend from sleeping: upgrade the service to **Starter** ($7/month)
or use a free uptime monitor (UptimeRobot) hitting `/health` every 10 minutes.

## Database — Neon (recommended free option)

The repo is already wired to use Neon Postgres (free tier: 0.5 GB storage, 100
compute hours/month, no auto-sleep when active). Just paste your Neon
connection string into `DATABASE_URL` on the backend service.

Other free Postgres options that work the same way:
- Supabase: https://supabase.com (extra: realtime, auth, storage)
- Railway: https://railway.app ($5 free credit/month)
- Render Postgres: built-in, $7/month

## Troubleshooting

| Symptom | Likely cause | Fix |
|---------|--------------|-----|
| `Network Error` on UI | Backend is sleeping or CORS wrong | Open backend URL once to wake; verify `CORS_ORIGINS` |
| `Can't reach database` | Neon is sleeping | First connection wakes it; just retry |
| Build fails on Render | Memory limits on free tier | Upgrade to Starter or simplify build |
| PDF generation fails | Chromium missing | The Dockerfile installs it; only an issue if you switched to Node runtime |
